# 아키텍처

공식 Mac TV 문서에는 Swift 패키지와 macOS 앱, 앱 상태·입력 라우팅, 기능별 코디네이터, 웹 리모컨 리소스가 설명되어 있다. 아래 경계는 이 구조에 기반한 조사 계획이다. 적용할 커밋의 실제 파일과 동작은 소스 확보 뒤 확인한다. [원본 기여 가이드](https://github.com/Arunprakaash/mac-tv/blob/main/CONTRIBUTING.md)

| 조사 지점 | 구현 방향 |
| --- | --- |
| 홈과 재생 | 앱 타일 등록, 웹 플레이어 선택, 외부 브라우저 실행과 홈 복귀 경로 재사용 |
| 웹 리모컨 | 기존 QR 페어링, 인증·권한 및 요청 흐름에 화면별 밝기 상태와 명령 추가 |
| 디스플레이와 오디오 | 화면별 식별자와 조절 가능 상태 조회. 내장과 외장 제어를 분리하고 기존 시스템 음량 경로 유지 |
| 상태 표시 | 성공 또는 확인된 상태를 리모컨과 OSD에 반영. 조회 불가·권한 없음·장치 제거를 구별 |
| 윈도우와 Spaces | 포커스를 가져오지 않는 화면별 오버레이를 후보로 확인. 원본 플레이어와 외부 전체화면에서 각각 검증 |

## OTT와 유튜브

국내 OTT 네 종은 `Catalog.services`에 일반 웹 타일로 등록한다. 초기 설정, 홈, 아이폰의 앱 목록은 기존 카탈로그 경로를 사용한다. 프로필에서 선택한 내장 또는 외부 웹 플레이어가 해당 공식 사이트를 연다. 네 타일의 이름과 실행 이벤트는 기존 사용 통계에서 제외한다. [웨이브](https://www.wavve.com) · [왓챠](https://watcha.com) · [티빙](https://www.tving.com) · [라프텔](https://laftel.net)

플레이어별 로그인, 쿠키 유지, DRM, 화질, 전체화면, 방향키 조작을 확인한다. 내장 웹 플레이어가 실패하면 원본의 외부 브라우저 경로를 검토한다. DRM 우회는 범위에서 제외한다.

| 유튜브 경로 | 확인 결과 |
| --- | --- |
| 내장 WebKit + 기존 유니콘 Pro | 공식 `/tv`와 원본 TV 사용자 에이전트로 내장 화면을 로드한다. 기존 타일과 프로필 WebKit 저장소를 사용한다. 유니콘 Pro 1.17.1은 앱별 광고 필터 설정을 지원한다. 실제 TV 재생의 차단 효과는 켜기·끄기 비교로 판정한다. [유니콘 Pro 앱별 차단 설정](https://support.getunicorn.app/hc/ko/articles/39541748392345) |
| Chrome + RemotePlayback + 유니콘 Pro | MIT 확장 프로그램이 TV 화면용 사용자 에이전트와 페이지 속성을 변경한다. 현재 Mac TV의 외부 플레이어는 `/tv`를 일반 페이지로 바꾸므로 이 경로를 쓰려면 별도 실행 경로와 확장이 필요하다. [RemotePlayback](https://github.com/aarshivv/remote-playback) |
| VacuumTube | MIT 데스크톱 래퍼에 Leanback과 자체 광고 차단이 있다. 배포자가 macOS 빌드를 미서명으로 안내하며, 채택 시 별도 앱의 입력과 홈 복귀를 검증해야 한다. [VacuumTube](https://github.com/shy1132/VacuumTube) |

동일 아이폰 리모컨에서 탐색, 재생, 홈 복귀가 가능한 후보를 선택한다. 외부 앱이나 브라우저는 Mac TV가 연 창의 상태를 구분하고 사용자의 다른 창과 세션을 보존한다. 입력 전달에 필요한 권한을 좁혀 검증한다.

## 화면 제어와 OSD

- 맥북 내장 화면 밝기는 비공개 `DisplayServices` 읽기·쓰기 심볼을 런타임에 찾는다. 심볼이나 실제 읽기 결과를 확인할 수 없으면 조절 불가로 표시한다.
- 외장 화면은 로컬에서 실행 중인 BetterDisplay CLI로 DDC VCP `0x10`을 우선 조회한다. 원시 밝기와 최대값을 확인하면 하드웨어 방식으로 조절한다. DDC 조회가 실패하면 BetterDisplay 메뉴의 일반 밝기와 같은 `brightness`를 읽고 쓴다. 표시한 방식과 일치하는 요청만 허용하고 같은 방식의 읽기 결과로 적용값을 확인한다. 두 방식 모두 활성 화면 UUID를 사용하며 CLI 호출은 앱 UI 스레드 밖에서 실행한다. [BetterDisplay CLI](https://github.com/waydabber/BetterDisplay/wiki/Integration-features,-CLI)
- 화면 목록 변경과 잠자기 복귀 시 캐시를 초기화한다. 웹 리모컨 밝기는 기존 신뢰 기기 인증을 적용하고 화면 UUID와 0–100 정수를 검증한다.
- 프리셋 터치와 길게 누른 뒤 드래그하는 동작은 같은 화면별 쓰기 경로를 사용한다. 드래그 중에는 표시값만 미리 보고 손을 뗄 때 한 번 쓴다. 현재값은 읽기 결과로 갱신하며, 쓰기 전에 시작된 조회 응답은 화면에 적용하지 않는다.
- 소프트웨어 밝기는 화면의 출력 영상을 감광하는 방식이다. HDR 및 색상 영향과 잠자기·재연결 이후 동작은 실기기로 확인한다.
- 밝기 쓰기의 읽기 확인 결과로 조절 화면 왼쪽에 OSD를 띄운다. 음량은 콘텐츠 창의 화면 오른쪽을 사용한다. 외부 브라우저와 IINA의 창 위치는 기존 손쉬운 사용 접근 범위에서 읽으며, 위치를 얻을 수 없으면 재생 대상으로 선택한 화면을 사용한다. IINA의 음량·음소거 값은 기존 전용 IPC로 읽는다.
- OSD는 키 창이 될 수 없고 마우스 입력을 받지 않는 AppKit 패널이다. 화면과 항목마다 패널을 재사용하고 마지막 갱신 후 2초에 닫는다. 화면 구성이 바뀌거나 화면이 잠자기에 들어가면 패널을 숨긴다. [Apple AppKit 창 동작](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)

## 연결과 빌드

- 기존 인증, 신뢰/게스트 권한과 재연결 흐름을 유지한다. 밝기 요청에서 화면 UUID와 값 범위를, 음량 슬라이더 요청에서 현재 내장 스피커의 Core Audio 출력 ID와 값 범위를 검증한다. 다른 출력으로 전환되면 이전 장치 ID의 요청을 거절한다. 음량 슬라이더의 상태와 요청은 신뢰 기기에서 사용한다. 리모컨은 신뢰 LAN에서 사용한다.
- `./build.sh --custom`은 `local.couch.tv.custom` 번들로 로컬 앱을 만든다. 별도 Application Support 디렉터리, 번들별 `UserDefaults`와 WebKit 저장소, 네트워크 공유·Jellyfin용 키체인 서비스를 사용한다. 원본 업데이트 UI와 조회는 커스텀 번들에서 비활성화하며 패키징 시 원본 TelemetryDeck 앱 ID를 빼고 라이선스를 포함한다.
- 새 앱은 스테이징에서 서명 검증을 끝낸 뒤 `build/`에 배치한다. `./build.sh --custom`은 커스텀용 로컬 인증서가 있으면 사용하며, 없으면 임시 서명한다. 반복 설치 후 권한 유지 여부는 사용한 서명과 macOS 권한 상태에 따라 확인한다.
